# Service Layer Code Map

Scope: focused domain services under `src/janus/services/`.

## Responsibilities

- provide reusable business logic that routers can call without owning persistence/auth details
- centralize auth and email service behavior
- define base abstractions used by service implementations

| `knowledge_retrieval.py` | Hybrid retrieval over knowledge chunks (JAN-243): metadata-filtered candidates, direct vector+substring ranking, graph expansion from query-matched entities (1–2 hops), RRF fusion, cited hits, entity resolution by id/name/alias, and entity detail (relations both ways, sources) |
| `knowledge_provenance.py` | Read-only knowledge-stack views (JAN-334), owner-scoped: `page_provenance_for_user` resolves a wiki page's `[n]` citations to the live passage or memory fact with the entities and facts behind the page, and `graph_for_user` returns active/pinned topics, their most connected entities, and the persisted topic-evidence and entity-relation links |
| `wiki_service.py` | Wiki pages (JAN-244): automatic pages for active/pinned topics and busy entities, page lookup and listing, user edits, Janus/agent proposals with accept/dismiss, restore from history, and removal of pages whose subject is gone |
| `docs_service.py` | Read-only access to `docs/docs` shared by `api/docs.py` and the `docs` agent toolbox (JAN-297): path confinement (no `..`, absolute, or outward-symlink escapes; only the `tech-spec.md` → root `TECH_SPEC.md` and `changelog.md` → root `CHANGELOG.md` aliases), nav parsing, page listing, heading sections and anchors, and the agent-only `reviews/` exclusion |
| `wiki_synthesis.py` | The Wiki synthesis built-in's work (JAN-244): per-page inputs (topic evidence and search hits, or entity mentions and relations, plus the subject's memory facts via `page_facts`, JAN-334), input hashing for staleness, the cited-page prompt, citation checking, publishing or proposing within the shared knowledge budget, and the synthesis settings |
| `memory_service.py` | Durable agent-memory fact storage, listing/search (owner/status/`source` filters bound the candidates, ranking via `knowledge_index.search_ids`), deletion, and background compaction helpers |
| `whatsapp_service.py` | WhatsApp account CRUD (owner-scoped `get_account_for_user`, `update_account_for_user`, `delete_account_for_user`; JAN-288), live-connector lifecycle, conversation/message list serialization, and `send_text` (send a text message into an owned conversation or to an international number via `phone_to_jid`, stored as outgoing, JAN-360) |
| `whatsapp_setup_service.py` | Transient WhatsApp QR-pairing setup-session lifecycle (create, poll, expire) |
| `base.py` | Shared service base patterns and common utilities |
